Why oneClient

Seven apps open. One window needed.

Backend work means a database IDE, a Kafka tool, a Redis browser, an API client, Docker Desktop, a terminal and a Git UI — each with its own login, shortcuts and window. oneClient puts them in one place, built like the editor you already know.

New · Fast Aggregates

Edit a whole Order — not four tables.

Right-click a table. oneClient reads your foreign keys and builds the aggregate: a paged list of orders; each order opens into a form with its items, payments and tags underneath — and every child opens the same way.

  • Navigate like a document. Order › Items › Notes, with a breadcrumb back up.
  • One-to-many and many-to-many. Add, edit and delete children; link tags through the join table.
  • Parents by name. Pick the customer from a searchable list — or create the missing one in a dialog, without losing your order.
  • Typed inputs. Date pickers, number fields, booleans, JSON — straight from the column types.
  • Safe by default. Delete previews what goes with a row, unsaved edits ask before you leave, and database errors read like sentences.

Works with PostgreSQL, SQL Server and MySQL. The configuration is a plain .aggregate.json you can commit.

New · Pipelines & test containers

Turn a test scenario into a pipeline.

Run a script, start a throwaway container, seed data, call your REST API and assert on the response — as ordered steps with variables, retries and teardown, like a CI job you can run from your desk.

  1. shell Check the toolchain
  2. container Start postgres:16, wait until it accepts connections
  3. shell Seed data with PowerShell or bash
  4. http POST /orders → assert status = 201
  5. cleanup Containers are removed — even if a step failed
  • Scripts in PowerShell, pwsh, bash, sh or cmd
  • A container's ports become variables: {{steps.db.endpoint}}
  • Assert on status, JSON paths, headers, timing and exit codes
  • Live output, run history and a notification when it finishes

Built to be extended

Your tool isn't here yet? Write the plugin.

The core has no tool-specific code at all. A plugin declares what it contributes in a manifest and implements it with a small, typed API — tasks, notifications, output channels, secrets, the workspace and other plugins' connections are all one call away.

  • One typed package: @oneclient/plugin-api
  • UI in any web framework, hosted in an isolated view
  • Plugins can offer tools to each other and to the AI assistant
  • Load, enable and disable live — no restart
Read the plugin API →
src/main.ts
export function activate(context: PluginContext) {
  context.registerCommand({
    commandId: "hello.run",
    async execute() {
      await context.tasks.run(
        { title: "Say hello", cancellable: true },
        async (task) => task.log("Hello from a plugin\n"),
      );
      await context.notifications.success("Done", {
        actions: [{ label: "Show output", commandId: "hello.output" }],
      });
    },
  });
}

Questions

Frequently asked questions

Is there a free, open-source alternative to a separate database client, Kafka UI, Redis GUI and Postman?

oneClient combines them in one VS Code-style app: PostgreSQL, SQL Server and MySQL / MariaDB clients, Apache Kafka, Redis, an HTTP client with Postman import, Docker, Azure Blob Storage and Keycloak. It is MIT-licensed and free.

What is a Fast Aggregate?

Right-click a table and oneClient reads your foreign keys to build an editable aggregate: a paged list of the root rows, a form for each row, and its related tables — one-to-many and many-to-many — as tabs that open the same way. For example an Order with its Items, their Notes and its Tags. The configuration is a plain .aggregate.json file you can edit and commit.

Does oneClient collect telemetry or need an account?

No. There is no account and no telemetry. Connection passwords are encrypted with your operating system's keychain, and the AI assistant only talks to the provider you configure with your own API key.

Does oneClient run in the browser?

Yes. Besides the desktop app for Windows, macOS and Linux, there is a self-hosted web version: a small Node server you open from any browser, with a Dockerfile included.

Which databases are supported?

PostgreSQL (including Azure Database for PostgreSQL, AWS RDS / Aurora, Supabase, Neon and TimescaleDB), Microsoft SQL Server, and MySQL / MariaDB, with query windows, a table data editor, CSV import, execution plans and SSH tunnels.

Can an AI assistant work with my databases and files?

The AI Assistant plugin chats with Claude, OpenAI, Gemini, DeepSeek, Kimi, GLM, Grok, Mistral, Qwen, OpenRouter, Ollama or any OpenAI-compatible server, using your own API key. It can list tables, run read-only SQL and propose file edits — anything that changes data waits for your approval.

Can I write my own plugin?

Yes. Plugins declare connection types, explorer trees, editors, commands, menus and title-bar quick actions in a manifest, and run in their own process. The plugin API is a typed package, @oneclient/plugin-api.
